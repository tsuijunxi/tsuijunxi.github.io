深入理解 Objective-C Block 与 C++ Lambda

发表于 2022-02-14 | 分类于 OC ， C++
字数统计: 3.5k | 阅读时长 ≈ 13 mins.
中文 / English

背景

Objective-C++ 允许在同一个翻译单元中同时使用 Objective-C 和 C++。这种能力省去了跨语言桥接层，但并不会合并两套对象模型：Objective-C 对象仍由 ARC 和 Objective-C Runtime 管理，C++ 对象仍遵循构造、拷贝、移动与析构规则。

真正容易出错的地方，是两种闭包开始捕获对方语言中的对象。例如，C++ lambda 捕获 Objective-C 对象时是否会触发 ARC？Objective-C Block 捕获 shared_ptr 或 weak_ptr 时会调用拷贝构造还是移动构造？这些行为又会不会形成循环引用或悬垂引用？

本文通过编译器展开结果、汇编和引用计数变化回答这些问题，重点讨论两类场景：

  1. C++ lambda 捕获 Objective-C 对象；
  2. Objective-C Block 捕获 C++ 对象。

实验范围：Objective-C++、C++14 与 ARC。

先看结论

对比项 Objective-C Block C++ lambda
运行时形态 带有调用入口和捕获数据的 Objective-C 对象 编译器生成、重载了 operator() 的闭包对象
默认捕获 普通自动变量按值导入；__block 变量通过转发存储共享 根据捕获列表按值或按引用保存
生命周期 存在全局、栈和堆等实现形态；ARC 负责多数复制与释放操作 遵循普通 C++ 对象的作用域、拷贝、移动与析构规则
捕获另一种语言的对象 捕获 C++ 对象时调用相应的拷贝或移动构造 Objective-C 指针字段按照其 ARC 所有权修饰符管理
主要风险 C++ 对象的复制成本、__block 转发和所有权变化 强捕获造成循环引用，引用捕获造成生命周期风险

内存管理

Objective-C Block 是 Objective-C 对象，运行时存在全局、栈和堆等不同实现形态。需要延长栈 Block 的生命周期时，复制操作会把它及其捕获数据迁移到堆上；在 ARC 下，这些复制与释放通常由编译器自动管理。被强捕获的 Objective-C 对象会随 Block 一起保持有效，直到相应所有权被释放。

C++ lambda 则是普通的闭包对象。按值捕获的变量成为闭包对象的成员，并随闭包对象执行拷贝、移动和析构；按引用捕获不会延长外部变量的生命周期。如果 lambda 在外部变量销毁后仍访问该引用，行为是未定义的，严重时会直接崩溃。例如：

捕获 this 本质上只保存一个原始指针，同样不会延长对象生命周期。无论对象位于栈上还是堆上，只要 lambda 可能晚于对象执行，就需要通过其他所有权机制保证其有效性，例如捕获适当的智能指针。

Objective-C++ 中的跨语言捕获

前面的例子都停留在各自的对象模型中。实际的 Objective-C++ 工程却经常需要跨语言捕获：lambda 保存 Objective-C 对象，或者 Block 保存 C++ 对象。此时 ARC 与 C++ 特殊成员函数会同时参与，生命周期关系也更容易被误判。

C++ lambda 可以捕获 Objective-C 对象，但捕获方式会决定是否建立强引用，以及 lambda 能否安全地晚于外部变量执行。

结论

C++ lambda 会生成一个闭包对象，并把捕获项保存为字段。在 Objective-C++ 与 ARC 环境下，Objective-C 对象指针字段仍然保留自己的所有权修饰符，编译器会在闭包对象的构造、复制、移动和析构过程中生成对应的 ARC 操作。

因此可以得到三点结论：

  1. 按值捕获普通 Objective-C 对象指针通常会形成独立的强引用，可能引发循环引用；
  2. 按值捕获 __weak 指针会保留弱引用语义，可以用于打破循环；
  3. 按引用捕获不会建立独立强引用，但要求外部变量在 lambda 执行期间始终有效，否则会产生悬垂引用。

使用 __block

使用 __block 后，Block 可以修改被捕获的 C++ 变量。根据 Clang 的 Block 语义，在 C++11 环境下，__block 变量迁移到转发存储时会优先按 xvalue 移动；无法移动时才尝试复制。

由此可以得到以下结论：

  1. Objective-C Block 可以通过 __block 转发存储共享 C++ 对象；
  2. 初始化 monitor 时，weak_count = 1；初始化 weakMonitor 后，weak_count = 2；Block 捕获后仍为 2；
  3. 迁移 __block 存储时触发的是移动构造，所有权发生转移，但引用计数不会额外增加。

被捕获的 C++ 对象何时释放？

Objective-C Block 销毁时，也会析构保存在捕获区中的 C++ 对象。

捕获 shared_from_this

C++ 的 this 是原始指针，Block 捕获它并不会自动延长对象生命周期。需要共享所有权时，可以通过继承 std::enable_shared_from_this 获取受 shared_ptr 管理的当前对象。

C++ 类需要继承 std::enable_shared_from_this<T>，并且对象本身已经由 std::shared_ptr 管理，才能安全调用 shared_from_this()。

根据前面的结论，在 CppClass::attachOCBlock 中直接捕获 shared_from_this() 同样可能形成循环引用。解决方式仍然是让 Block 捕获 std::weak_ptr，执行时再临时提升为 std::shared_ptr。

结论

Objective-C Block 可以保存 C++ 对象，但具体行为取决于捕获方式：

  1. 普通捕获会把 C++ 对象复制进 Block 的捕获区，并调用相应的拷贝构造函数；
  2. __block 捕获会通过转发存储共享变量。在 C++11 环境下，存储迁移时会优先调用移动构造函数；
  3. 捕获原始指针不会延长对象生命周期，捕获 shared_ptr 则可能参与形成循环引用。

总结

Objective-C++ 允许两种语言写在同一个文件中，但不会替我们统一它们的对象模型。跨语言捕获时，ARC 所有权修饰符、C++ 特殊成员函数和闭包自身的生命周期会同时生效。

判断这类问题时，与其只看捕获语法，不如依次回答三个问题：闭包对象实际保存了什么字段？复制或迁移闭包时调用了哪些操作？闭包与被捕获对象之间最终形成了怎样的所有权关系？只要把这三层关系展开，循环引用、悬垂引用和额外复制通常都能被准确定位。
