Network Callback Flow

LWConnectionInternal has a LWConnectionInternalDelegate internally, and it delegates the network result to LWURLConnection.

Using internal_connectionDidFinishLoading as an example, it wraps the delegate method of LWURLConnection, which is the outer business layer, into an LWMessage, then calls the familiar [_runloop postMessage:msg], sending it into the RunLoop message queue.

So LWURLConnection itself performs network requests based on socket and select. Once the network result comes back, it interacts with the RunLoop again: the delegate method is wrapped as a message and added to the RunLoop message queue. What happens next is handled by the RunLoop itself.

LWPort

The most basic concept in Mach is the message. Messages are passed between two ports. By design, any two ports can pass messages to each other, whether they are on the same machine or on a remote host. The source code discussed here uses ports on the same machine.

Sending a message from one port to another is essentially placing the message into a queue until the receiver can process it.

For example, CFRunLoop has two kinds of CFRunLoopSource:

  • source0: handles events such as UIEvent and CFSocket.
  • source1: Mach-port-driven, such as CFMachPort and CFMessagePort.

From the name alone, source1 is clearly related to ports.

LWSocket

Now look at the initialization of LWSocket:

  • For the leader, the main job is to define a socket, open a network communication port, bind a fixed network address such as 127.0.0.1 and port 8082, then call listen to listen for requests.
  • For the follower, the main job is to define a socket with an automatically assigned port, then call connect to connect to the server. connect and bind have similar parameter forms. The difference is that bind receives the local address, while connect receives the peer address.
  • This is very typical socket programming.
