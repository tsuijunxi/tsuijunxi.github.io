Preface

Lexical analysis is the first task a compiler performs. After preprocessing source code, such as removing comments, unnecessary line breaks, and locating included files, lexical analysis decomposes the whole source program into words. These words fall into five categories: identifiers, keywords, constants, operators, and delimiters. This prepares the input for syntax analysis and semantic analysis.

Lexical analysis works on individual characters. Its purpose is to combine those characters into valid words, or strings. The main task of this stage is therefore to build a lexer. There are two common approaches:

  • Write it manually. For a specific language such as JavaScript, we write code by hand and simulate the conversion process according to the language rules. This is complex and error-prone, but it gives precise control over every part of lexical analysis and can be efficient.
  • Generate a lexer automatically. The process is: declarative specification -> automatic generation -> lexer. The generator accepts declarative rules as input and outputs a lexer. A declarative specification means that we only describe the rules for recognizing character streams, not how to recognize them. The rules are regular expressions. Keywords, identifiers, and integers in C can all be described by regular expressions. These regular expressions are fed into the generator, which produces a lexer, usually a DFA, or deterministic finite automaton. The overall process is: regular expression -> NFA -> DFA -> minimized DFA. If the input code is accepted by the finite automaton, it enters the syntax-analysis stage.

The most famous tools for lexical and syntax analysis are lex/yacc, along with their successors flex/bison. They provide language and text parsing capabilities for many pieces of software. They are powerful and interesting.

Although JavaScriptCore does not use them and instead implements its own lexer, the basic ideas are similar.
