dispatch_semaphore_create

This creates a counting semaphore with an initial value. If two threads need to finish one job together, you can use a semaphore whose initial value is 0. If you need to manage a limited resource pool, use an initial value equal to the size of the resource pool. When the semaphore is no longer used, call dispatch_release to destroy it and release its memory. Under ARC this is not needed, because the system releases it automatically.

The flow is:

dispatch_semaphore_wait

This waits on a semaphore, or decreases the semaphore count. Each call decrements the counter by 1. If the counter becomes less than 0 after the decrement, the current thread blocks until a signal is received.

This function atomically decrements the semaphore value. If the value is greater than or equal to 0, it means a resource is available and the function returns directly. Otherwise, it calls _dispatch_semaphore_wait_slow and waits for a signal in the FIFO queue until the timeout is reached.

After entering _dispatch_semaphore_wait_slow, the behavior depends on the timeout type:

    1. DISPATCH_TIME_NOW: check immediately and return without waiting. If dsema_value is less than 0, increment it by 1 and return the timeout signal KERN_OPERATION_TIMED_OUT.
    1. DISPATCH_TIME_FOREVER: wait indefinitely until dsema_value becomes greater than 0. Once a signal arrives, it jumps to again and runs the function flow again.
    1. Timed wait: wait until either a signal arrives or the timeout expires.

dispatch_semaphore_signal

This sends a signal, or increases the count of a semaphore. If the semaphore value before incrementing, dsema_value, is greater than or equal to 0, no thread is blocked by this semaphore, so it returns directly.

If the semaphore value before incrementing is less than 0, _dispatch_semaphore_signal_slow is called. It wakes one thread waiting in dispatch_semaphore_wait. If multiple threads are waiting, iOS decides which one to wake based on thread priority.

Summary

GCD semaphores are relatively simple. Just remember these three key APIs: create, wait, and signal.
