Related API Analysis

dispatch_group_create

This was mentioned once in the opening article, mainly when analyzing the essence of dispatch_group_s. We learned that dispatch_group_t is essentially a semaphore whose value is LONG_MAX. So it is easy to imagine that semaphore behavior is inseparable from the analysis of dispatch_group_t.

The low-level implementation of semaphores is analyzed in a separate article.

dispatch_group_enter

First, dispatch_group_t is converted into dispatch_semaphore_t, and then dispatch_semaphore_wait is called.

This function atomically decrements the semaphore value. If it is greater than or equal to 0, a resource is available and it returns directly. Otherwise it calls _dispatch_semaphore_wait_slow, waiting for a signal in the FIFO queue until timeout. For details about _dispatch_semaphore_wait_slow, see the dispatch_semaphore article.

dispatch_group_leave

This indicates that one block task in the group has completed, and sends a wake-up signal when necessary. In dispatch_group_leave, the group’s semaphore is incremented by 1. Then it checks whether the current semaphore value is equal to the original group semaphore value. If they are equal, it means the tasks are complete, and the wake-up flow _dispatch_group_wake begins.

_dispatch_group_wake mainly does two things:

  • It wakes semaphores through semaphore_signal.
  • It calls dispatch_async_f in sequence.

dispatch_group_async is a wrapper around dispatch_group_async_f.

Inside dispatch_group_async_f, the main operations are:

  • Call dispatch_group_enter to manage the semaphore reference count.
  • Create a dispatch_continuation_t to record the group the block belongs to, its context, invocation function, and related information.
  • Call _dispatch_queue_push to enqueue the dispatch_continuation_t.

Do you still remember the implementation of dispatch_async_f?

You can see that dispatch_group_async_f and dispatch_async_f are highly similar. The main difference is that dispatch_group_async_f calls dispatch_group_enter first.
